## Relationships

| From | Relationship | To | Description |
|---|---|---|---|
| sys_admin | performs_action | audit_log_01 | Admin's action is recorded in the audit log |
| audit_log_01 | target | cyber_helmet | The model is the target of the audit action |
| sys_admin | reviews | report_01 | Admin processes the pending report |
| report_01 | target | cyber_helmet | The report points to the model |
| sys_admin | generates | platform_stats | Admin triggers stats aggregation |
| sys_admin | approveUser / suspendUser | cyber_artist | Admin manages artist account status |

## System Behavior Notes

- When an admin approves a model, the system calls `model.update({ status: APPROVED })` and creates an `Admin_Audit_Log` entry. The diagram shows both the approval action (audit_log `action = APPROVE_MODEL`) and the model's earlier pending state.
- The `Report` record with `status = "Resolved"` reflects a Report that the admin has reviewed and closed. This maps to `Report_Status.REVIEWED` in the schema.
- The `platform_stats` object captures a full month period. The `data` field (not shown here) would contain a JSON structure with totals for orders, revenue, new users, and top models.
- Admin audit logs are append-only. The `admin_id` FK on `Admin_Audit_Log` connects back to the admin user, enabling the audit log viewer in the dashboard.
